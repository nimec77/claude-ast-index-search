# PRD: CS-3-3 -- Flutter-Specific Slash Command Examples in initialize-flutter Plugin Command

**Status:** PRD_READY
**Ticket:** CS-3-3
**Created:** 2026-03-01

---

## Context / Idea

**Arguments:** CS-3-3

This ticket is part of Phase 3 (Claude Code Plugin Integration) of the Flutter/Dart support feature. The goal of Phase 3 is to provide an `initialize-flutter` plugin command with Flutter-specific rules and slash commands.

**From description file (`docs/phase/phase-3.md`):**

> **Phase 3 Goal:** Provide a `initialize-flutter` plugin command with Flutter-specific rules and slash commands.
>
> **Task 3.1:** Create `plugin/commands/initialize-flutter.md` -- document Flutter project setup steps, recommended `CLAUDE.md` snippets, and common `ast-index` invocations for Flutter codebases
>
> **Task 3.2:** Add Flutter-specific search rules to the plugin command (e.g. widget class detection, provider/bloc pattern hints)
>
> **Task 3.3:** Add Flutter-specific slash command examples (e.g. `ast-index search --kind Class --lang dart`)
>
> **Task 3.4:** Verify `plugin/SKILL.md` (or equivalent index) references the new `initialize-flutter` command

CS-3-3 specifically focuses on enriching the `initialize-flutter` plugin command (created in CS-3-1 and extended in CS-3-2) with concrete slash command examples that demonstrate how to use `ast-index` for common Flutter development tasks. These examples should appear in the `.claude/rules/ast-index.md` rules file content within the `initialize-flutter.md` command template, specifically in the Flutter-specific commands table section.

**Current state of the plugin:** The plugin already includes `initialize-android`, `initialize-ios`, `initialize-web`, `initialize-rust`, `initialize-ruby`, and `initialize-csharp` commands in `plugin/commands/`. Each follows an identical structure: prerequisites check, settings.json creation, rules file with a command reference table and platform-specific commands table, index build, and verification. A `references/dart-commands.md` file already exists in `plugin/skills/ast-index/references/` documenting Dart-specific AST index capabilities.

**Dependencies:** CS-3-1 (create the `initialize-flutter.md` file) and CS-3-2 (add Flutter-specific search rules) must be completed first, as CS-3-3 adds command examples to the Flutter-specific section of the rules content within that file.

---

## Goals

1. Add a comprehensive table of Flutter-specific slash command examples to the `initialize-flutter.md` plugin command's rules section.
2. Cover the most common Flutter development workflows: finding widgets, BLoC/Provider patterns, state management classes, navigation, mixins, extensions, and module dependencies.
3. Follow the established pattern used by other platform-specific initialize commands (Android, iOS, Web) where a platform-specific commands table is included in the rules content.
4. Ensure the examples use valid `ast-index` CLI syntax that works with the Dart parser capabilities documented in `references/dart-commands.md`.

---

## User Stories

1. **As a Flutter developer using Claude Code**, I want the `initialize-flutter` setup to include example commands for common Flutter tasks, so that I can immediately start searching my codebase without memorizing the CLI syntax.
2. **As a Claude Code user in a Flutter project**, I want the rules file to contain Flutter-specific command examples, so that the AI assistant can reference them when helping me search for widgets, BLoCs, providers, and other Flutter patterns.
3. **As a developer new to ast-index**, I want to see concrete command examples for Flutter-specific concepts (StatelessWidget, ChangeNotifier, BLoC, etc.), so that I understand how ast-index maps to Flutter's architecture patterns.

## Constraints

1. **File to modify (per description file):** `plugin/commands/initialize-flutter.md` -- the Flutter-specific commands table must be added within the rules file content section (step 3 of the initialize command).
2. **Format consistency:** The commands table must use the same `| Task | Command |` two-column markdown table format used by `initialize-android.md` (Android-Specific Commands), `initialize-ios.md` (iOS-Specific Commands), and `initialize-web.md` (TypeScript/JavaScript-Specific Commands).
3. **Valid CLI syntax:** All example commands must use subcommands and flags that actually exist in `ast-index`. The Dart parser supports: `class`, `search`, `symbol`, `usages`, `implementations`, `hierarchy`, `callers`, `outline`, `imports`, `refs`, `map`, `conventions`, `modules`, `deps`.
4. **No `--kind` or `--lang` flags:** Despite the phase-3.md description mentioning `ast-index search --kind Class --lang dart`, the actual `ast-index` CLI does not have `--kind` or `--lang` flags on the `search` subcommand. The correct approach is to use the `class` subcommand for class searches and the `symbol` subcommand for other kinds. The examples must reflect the actual CLI interface.
5. **Content source for examples:** Examples should be derived from the capabilities documented in `plugin/skills/ast-index/references/dart-commands.md` and the core command reference in `plugin/skills/ast-index/SKILL.md`.
6. **Dependencies:** CS-3-1 (file creation) and CS-3-2 (search rules) must be completed before this task, as CS-3-3 adds content to sections established by those tasks.

---

## Risks

1. **CLI flag mismatch:** The phase-3.md description uses `--kind Class --lang dart` as an example, but the actual `ast-index` CLI does not support these flags on the `search` subcommand. Mitigation: use the correct CLI syntax from the existing documentation and test examples against `ast-index help`. Note this divergence from the description file example, which appears to be illustrative rather than prescriptive.
2. **Overlap with CS-3-2 (search rules):** The boundary between "search rules" (CS-3-2) and "slash command examples" (CS-3-3) may be ambiguous. Mitigation: CS-3-2 should focus on the textual rules and guidelines in the rules file (e.g., "use ast-index first", "widget detection hints"), while CS-3-3 focuses on the concrete command examples table.
3. **Dart parser coverage gaps:** Some commands may not return results if the Dart tree-sitter parser does not index certain constructs. Mitigation: only include examples for constructs documented as supported in `references/dart-commands.md` (classes, mixins, extensions, extension types, enums, typedefs, functions, constructors, imports).
4. **State management framework variety:** Flutter has many state management solutions (BLoC, Provider, Riverpod, GetX, Redux, MobX). The examples cannot cover all. Mitigation: focus on the most common patterns (BLoC, Provider/ChangeNotifier) and include a generic "find implementations" example that works for any base class.
