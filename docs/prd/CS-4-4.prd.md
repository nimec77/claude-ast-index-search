## Metrics

- `cargo clippy -- -D warnings` exits with code 0 and zero warning lines in stderr.
- `cargo clippy --tests -- -D warnings` exits with code 0 and zero warning lines in stderr.
- `cargo fmt --check` exits with code 0 (no files need reformatting).
- `cargo test` exits with code 0 (all tests pass).
- No new `#[allow(...)]` annotations are added to suppress warnings (warnings should be fixed, not suppressed).

---

## Constraints

1. **Commands to run (per description file):** `cargo clippy -- -D warnings` and `cargo fmt` -- zero new warnings, all formatting clean.
2. **Additional lint scope (per CLAUDE.md):** `cargo clippy --tests -- -D warnings` must also be run to cover test code.
3. **No behavioral changes:** Any fixes applied to satisfy clippy must not change the functional behavior of the code. If clippy suggests a refactoring that would alter semantics, it should be noted and skipped.
4. **No warning suppression:** Do not add `#[allow(clippy::...)]` attributes to suppress warnings. Fix the underlying issue instead.
5. **Dependency on 4.1-4.3:** This task should be run after tasks 4.1, 4.2, and 4.3 are complete, since their new code must also be verified.
6. **Formatting standard:** Use the project's default `rustfmt` configuration (no custom `rustfmt.toml` overrides unless one already exists in the project).

---

## Risks

1. **Clippy version differences:** Different Rust toolchain versions may produce different clippy warnings. Mitigation: use the same toolchain version that CI uses; document the Rust version if warnings appear that are version-specific.
2. **False positives from clippy:** Clippy may flag code patterns that are intentional (e.g., explicit type annotations for clarity). Mitigation: evaluate each warning individually; if a fix is genuinely harmful to readability, document the reasoning (but do not suppress without team consensus).
3. **Cascading changes from lint fixes:** A clippy fix in a core module (e.g., `indexer.rs`, `db.rs`) could theoretically affect downstream behavior. Mitigation: run the full test suite (`cargo test`) after every fix to catch regressions immediately.
4. **New warnings from upstream dependency updates:** If `Cargo.lock` is updated between Phases 3 and 4, new transitive dependencies could trigger clippy warnings in generated code. Mitigation: this task only covers warnings in the project's own code (`ast-index` crate), not in dependencies.
