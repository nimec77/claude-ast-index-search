### NC-3: `ast-index class "Mixin"` limitation is acceptable

**Check:** The command `ast-index class "Mixin"` finds mixins only by naming convention (those whose name contains "Mixin"). This is a documented limitation. The alternative `ast-index search "mixin"` from `dart-commands.md` would find all mixin declarations. The Flutter-Specific Search Rules textual section correctly documents this as "indexed as Interface kind".

**Result: ACCEPTABLE (documented limitation).** The plan explicitly documents this trade-off. The limitation is consistent with how other platform commands work (e.g., Android's `class "Controller"`). The `dart-commands.md` reference documents `ast-index search "mixin"` as the alternative for finding all mixins, but the command table uses `ast-index class "Mixin"` for convention-based discovery, which is a valid UX choice.

**Minor observation:** The Flutter/Dart-Specific Commands table uses `ast-index class "Mixin"` (finds by name convention) while `dart-commands.md` shows `ast-index search "mixin"` (finds all mixin declarations). Neither is wrong, but the two approaches serve different purposes. A user following the table literally may miss mixins not named with "Mixin" in their name. This is a minor documentation clarity issue, not a defect, since the textual rules section already explains the behavior.

## Risk Zone

### Risk 1 (LOW): call-tree command may produce empty results for Dart

The `ast-index call-tree "function" --depth 3` in the Command Reference table is not confirmed to work for Dart (SKILL.md lists supported languages as Kotlin, Java, Swift, Perl, ObjC). If a developer runs this for a Dart function name, they may get empty results without explanation. This is a pre-existing issue across all platform initialize commands, not introduced by CS-3-3. Impact: low confusion, no functional breakage.

**Mitigation:** Not addressed by this ticket. A follow-up ticket could add a note in the Command Reference table footnote or remove `call-tree` from Dart-specific documentation.

### Risk 2 (LOW): `ast-index class "Mixin"` finds only naming-convention mixins

As documented in NC-3, this command finds mixins only if their name contains "Mixin". Dart mixins can have any name (e.g., `Loggable`, `TickerProviderMixin`). A developer searching for all mixins in their project will miss those without "Mixin" in the name. The `dart-commands.md` reference correctly shows `ast-index search "mixin"` as the full-scan alternative.

**Mitigation:** The Flutter-Specific Search Rules section explains the indexing behavior ("indexed as Interface kind"), which provides enough context for sophisticated users. Acceptable for the scope of this ticket.

### Risk 3 (INFORMATIONAL): Pre-existing `--kind function` bug in initialize-web.md

`initialize-web.md` contains `ast-index search "use" --kind function`, which uses a non-existent `--kind` flag. CS-3-3 correctly avoids this pattern. The web command bug is noted for tracking purposes but is out of scope. If a developer uses the web command as a reference template for future platform commands, they may copy this bug.

**Mitigation:** Track as a separate defect. Not a risk for CS-3-3 delivery.

### Risk 4 (LOW): Riverpod `ConsumerWidget` in Flutter Project Detection section

The Flutter Project Detection section includes `ast-index search "ConsumerWidget"`. ConsumerWidget is Riverpod-specific and will only return results in Riverpod projects. This is expected behavior and is useful for detection purposes. No risk of false positives -- an empty result simply means Riverpod is not used.
