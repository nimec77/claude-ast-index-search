## Context

Phase 3 adds a `initialize-flutter` plugin command to `plugin/commands/`. This ticket implements all four Phase 3 tasks in a single file:

- Task 3.1: Create `plugin/commands/initialize-flutter.md` with the 5-step structure (prerequisites, settings.json, rules file, build index, verify)
- Task 3.2: Add Flutter-specific search rules (widget detection, provider/bloc pattern hints) as textual guidelines in the rules content
- Task 3.3: Add a Flutter/Dart-Specific Commands table with at least 8 rows in the rules content
- Task 3.4: Verify `plugin/skills/ast-index/SKILL.md` and `plugin/.claude-plugin/plugin.json` already reference or auto-discover the new command (no code changes needed)

The file must follow the exact structure of existing initialize commands (`initialize-android.md`, `initialize-ios.md`, `initialize-web.md`, `initialize-ruby.md`, `initialize-rust.md`, `initialize-csharp.md`).

**Deviation fixed by this ticket:** The PRD description file mentions `ast-index search --kind Class --lang dart`, but the actual CLI has no `--kind` or `--lang` flags on `search`. All example commands must use real CLI subcommands (`class`, `symbol`, `implementations`, etc.) validated against `src/main.rs`.

  Create the file `plugin/commands/initialize-flutter.md` with YAML frontmatter (`name: initialize-flutter`, `description: ...`) and the following 5 steps that match the structure of existing initialize commands exactly:
  1. Check Prerequisites (`ast-index version`, brew install instructions)
  2. Create/Update `.claude/settings.json` (identical JSON block to all other initialize commands)

- [x] **Task 2: Add Flutter-specific search rules to the rules content (Task 3.2)**

  Within Step 3 (the `.claude/rules/ast-index.md` content block) of `initialize-flutter.md`, add a "Flutter-Specific Search Rules" section with textual guidelines placed above the Flutter/Dart-Specific Commands table. Must include at least the following hints:
  - Use `ast-index implementations "StatelessWidget"` or `"StatefulWidget"` to find all widget implementations

  - Use `ast-index search "extension"` to find Dart extensions (indexed as Object kind)
  - Use `ast-index hierarchy "Widget"` to explore the widget inheritance tree
  - Use `ast-index conventions` to auto-detect BLoC, Provider, and other architecture patterns

  **Acceptance criteria:**
  - The rules content block in `initialize-flutter.md` contains a "Flutter-Specific Search Rules" section with at least 6 textual guidelines covering widget detection and state management patterns.
  - Each guideline references a valid `ast-index` CLI subcommand (no `--kind` or `--lang` flags on `search`).
