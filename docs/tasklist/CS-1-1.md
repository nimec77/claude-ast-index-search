# Tasklist: CS-1-1 -- Flutter/Dart Project Detection

**Ticket:** CS-1-1
**Status:** IMPLEMENT_STEP_OK
**Created:** 2026-03-01

---

## Context

Add Flutter/Dart project detection to `ast-index` by recognizing `pubspec.yaml` as a project marker file. This involves extending the `ProjectType` enum, detection logic, project root resolution, and build marker recognition. No Dart parsing is in scope for Phase 1 -- only project identification.

---

## Tasks

- [x] **Task 1.1 -- Add `Flutter` variant to `ProjectType` enum and `as_str()` in `src/indexer.rs`**

  Insert `Flutter, // Dart - pubspec.yaml` into the `ProjectType` enum between `Bazel` and `Mixed`, and add `ProjectType::Flutter => "Flutter (Dart)"` to the `as_str()` match block.

  Acceptance criteria:
  - `ProjectType::Flutter` compiles as a valid enum variant with no compiler warnings.
  - `ProjectType::Flutter.as_str()` returns the string `"Flutter (Dart)"`.

- [x] **Task 1.2 -- Add `pubspec.yaml` detection to `detect_project_type()` in `src/indexer.rs`**

  Add `let has_flutter = root.join("pubspec.yaml").exists();` after the Bazel detection block, include `has_flutter` in the count array for `Mixed` detection, and add `else if has_flutter { ProjectType::Flutter }` before the `Unknown` fallback.

  Acceptance criteria:
  - `detect_project_type()` returns `ProjectType::Flutter` when `pubspec.yaml` is the only project marker present (Scenario 1).
  - `detect_project_type()` returns `ProjectType::Mixed` when both `pubspec.yaml` and another marker such as `package.json` are present (Scenario 3).

- [x] **Task 1.3 -- Add `pubspec.yaml` check to `find_project_root()` in `src/main.rs`**

  Add the Flutter marker check block (checking `ancestor.join("pubspec.yaml").exists()`) in the ancestor walk loop, placed after the `.xcodeproj` check and before the Bazel markers block.

  Note: `find_project_root()` does not exist in `src/indexer.rs`; only `src/main.rs` requires this change (deviation from phase-1.md task 1.3 description is documented in the plan and requires no code fix).

  Acceptance criteria:
  - Running from a subdirectory of a Flutter project causes `find_project_root()` to return the ancestor directory containing `pubspec.yaml` (Scenario 2).
  - Existing project root resolution for Gradle, Xcode, and Bazel markers is unaffected (Scenario 5).

- [x] **Task 1.4 -- Add `pubspec.yaml` to `has_build_marker()` in `src/indexer.rs`**

  Append `|| path.join("pubspec.yaml").exists()` to the boolean chain in `has_build_marker()` after the `CMakeLists.txt` check.

  Acceptance criteria:
  - `has_build_marker()` returns `true` for a directory containing `pubspec.yaml` (Scenario 4).
  - `has_build_marker()` continues to return `true` for all previously recognized markers (no regression).

- [x] **Task 1.5 -- Add unit tests in `src/indexer.rs`**

  Add three new tests following the established `tempfile::TempDir` pattern:
  - `test_detect_flutter_project` -- creates `pubspec.yaml`, asserts `ProjectType::Flutter`.
  - `test_detect_mixed_flutter_and_frontend` -- creates both `pubspec.yaml` and `package.json`, asserts `ProjectType::Mixed`.
  - `test_has_build_marker_pubspec` -- creates `pubspec.yaml`, asserts `has_build_marker()` returns `true`.

  Acceptance criteria:
  - All three new tests pass under `cargo test`.
  - Test names and structure follow the conventions of existing parser and indexer tests.

- [x] **Task 1.6 -- Validation: zero regressions, lint, and formatting**

  Run the full validation suite:
  - `cargo test` -- all existing and new tests pass.
  - `cargo clippy -- -D warnings` -- zero new warnings.
  - `cargo fmt --check` -- no formatting changes required.

  Acceptance criteria:
  - `cargo test` exits with code 0 and no test failures.
  - `cargo clippy -- -D warnings` exits with code 0 (zero new warnings introduced by this ticket).
