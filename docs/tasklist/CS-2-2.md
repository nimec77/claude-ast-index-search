# Tasklist: CS-2-2 -- Flutter Module & Dependency Support (Phase 2 Complete)

**Ticket:** CS-2-2
**Status:** IMPLEMENT_STEP_OK
**Created:** 2026-03-01

## Context

Phase 2 adds full module support for Flutter projects. CS-2-2 implements:
1. YAML parsing to extract the `name:` field from `pubspec.yaml` (complete)
2. Dependency parsing to extract `dependencies:` and `dev_dependencies:` sections and write to `module_deps` (new scope)
3. Unit tests for both module name extraction and dependency parsing (new scope)

The implementation uses `serde_yaml_ng = "0.10.0"` in `Cargo.toml` and adds branches inside `index_modules_from_files()` and `index_module_dependencies()` in `src/indexer.rs`.

- [x] **Task 2: Implement `pubspec.yaml` branch in `index_modules_from_files()` (`src/indexer.rs`)**

  Add a new branch that checks `name_str == "pubspec.yaml"`, reads the file, deserializes it via `serde_yaml::from_str::<PubSpec>()` using a local `#[derive(serde::Deserialize)] struct PubSpec { name: Option<String> }`, and inserts `(name, module_path)` into the `modules` table via `INSERT OR IGNORE`.

  **Acceptance criteria:**
  - Running `ast-index index` on a Flutter project with `pubspec.yaml` containing `name: my_app` results in `ast-index modules` listing `my_app` with the correct relative directory path (Scenario 1).
  - A `pubspec.yaml` lacking a `name:` field (or with malformed YAML) is silently skipped -- no error is returned and no module row is inserted (Scenario 3).

- [x] **Task 3: Verify graceful handling of edge cases**

  Confirm that: (a) a `pubspec.yaml` with a complex structure (many fields) only extracts `name:` and ignores all other fields; (b) a root-level `pubspec.yaml` produces an empty string as the module path, which is acceptable.

  **Acceptance criteria:**
  - Parsing a `pubspec.yaml` containing `version:`, `description:`, `dependencies:`, etc. alongside `name: feature_auth` inserts only `feature_auth` as the module name, with no extraneous data (Scenario 4).
  - Root-level `pubspec.yaml` produces a module row with an empty path string and the correct name from the YAML `name:` field.

- [x] **Task 4: Verify no regressions in existing module parsers**

  Run the full test suite and confirm that Gradle (`build.gradle`, `build.gradle.kts`), SPM (`Package.swift`), and Perl (`.pm`) module parsing are unaffected by the new branch (Scenario 5).

  **Acceptance criteria:**

  - A project containing `build.gradle`, `Package.swift`, and `pubspec.yaml` has all three module types indexed correctly after `ast-index index`.

## Phase 2 Expansion Tasks

- [x] **Task 6: Implement `index_module_dependencies()` for Flutter (`src/indexer.rs`)**

  Add a branch inside `index_module_dependencies()` that handles `pubspec.yaml`. Parse the `dependencies:` and `dev_dependencies:` sections using `serde_yaml_ng`. For each package name found, insert a row into the `module_deps` table with the Flutter module name as the source and the package name as the dependency. Follow the existing branch-by-filename pattern (Gradle, SPM, etc.).

  **Acceptance criteria:**
  - `ast-index deps` on a Flutter project lists packages from `dependencies:` and `dev_dependencies:`.
  - Missing or empty dependency sections are handled gracefully (no error, no rows inserted).
  - Malformed YAML is silently skipped.

- [x] **Task 7: Add unit tests for `pubspec.yaml` dependency parsing**

  Add tests in `src/indexer.rs` (same test module as the existing pubspec tests) covering:
  - Basic dependency extraction: a `pubspec.yaml` with `dependencies: { flutter: sdk: flutter, http: ^0.13.0 }` produces the expected `module_deps` rows.
  - `dev_dependencies:` section is also indexed.
  - Missing `dependencies:` section: no rows inserted, no error.
  - Malformed YAML: silently skipped.

  **Acceptance criteria:**
  - `cargo test` green across all new and existing tests.
  - Tests use the same `make_modules_db()` / in-memory SQLite helper pattern as existing pubspec tests.
