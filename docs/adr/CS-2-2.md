# ADR: CS-2-2 -- YAML Crate Selection for Flutter Module Parsing

**Ticket:** CS-2-2
**Created:** 2026-03-01
**Status:** Decided

---

## Context

CS-2-2 requires adding a YAML parsing library to extract the `name:` field from `pubspec.yaml` files. The phase-2 description explicitly names `serde_yaml` as the crate to add. However, `serde_yaml` (by dtolnay) has been archived and is no longer maintained. A community fork, `serde_yml`, is the actively maintained replacement.

The project already uses `serde = { version = "1", features = ["derive"] }` and `serde_json = "1"`, so any serde-based YAML library integrates naturally.

---

## Options

### Option A: `serde_yaml` v0.9 (dtolnay, archived)

**Pros:**
- Explicitly specified in the phase-2 description and PRD
- Stable, well-tested codebase (v0.9.x)
- API is well-known in the Rust ecosystem
- Zero migration effort -- matches the description exactly

**Cons:**
- Repository archived, no new releases or bug fixes
- No security patches if vulnerabilities are discovered
- May eventually be yanked or conflict with future serde versions

### Option B: `serde_yml` v0.0.12+ (community fork, active)

**Pros:**
- Actively maintained with regular releases
- API is identical to `serde_yaml` for basic usage (drop-in replacement)
- Will receive bug fixes and security patches
- Future-proof choice

**Cons:**
- Deviates from the explicit requirement in the phase-2 description
- Younger project with less community adoption (though growing)
- Version is still pre-1.0 (0.0.x)

---

## Decision

**Chosen: Option A -- `serde_yaml` v0.9**

**Rationale:**
1. The phase-2 description and PRD explicitly specify `serde_yaml`. Requirements are authoritative and must not be reinterpreted.
2. For the narrow use case of extracting a single `name:` field from YAML, `serde_yaml` v0.9 is fully sufficient and stable.
3. Migrating to `serde_yml` in the future is trivial (rename the import, update `Cargo.toml`) if the team decides to do so.
4. The project does not require advanced YAML features or ongoing YAML library development.

**Migration path:** If `serde_yaml` is ever yanked or becomes incompatible, replace with `serde_yml` by changing `Cargo.toml` from `serde_yaml = "0.9"` to `serde_yml = "0.0.12"` and updating import paths from `serde_yaml::` to `serde_yml::`. The deserialization API is identical.
