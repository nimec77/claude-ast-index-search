## Limitations and Risks

### Risk 1: Nightly Toolchain Clippy Variance

The project uses `channel = "nightly"` which means clippy lints can change between nightly releases. The current nightly (`2026-02-28`) passes cleanly. If the nightly updates before the task is completed, new lints could appear. **Mitigation:** Pin to the current nightly date if needed, or fix any new warnings that appear.

### Risk 2: Pre-existing `#[allow(...)]` Annotations

Three existing `#[allow(clippy::...)]` annotations predate Flutter/Dart work. The PRD forbids adding NEW ones. These three should be left as-is since they are pre-existing and not part of this ticket's scope.

### Risk 3: Dependency on Tasks 4.1--4.3

The PRD states CS-4-4 should run after 4.1--4.3. Those test additions already exist in the codebase (added alongside implementation commits in Phases 1--2). The code has been passing lint checks since those commits. If additional test code is added for a dedicated 4.3 integration test, CS-4-4 would need to be re-run afterward.

### Risk 4: No Behavioral Changes Allowed

The PRD constraint #3 states any fixes must not change functional behavior. Since the codebase currently passes all checks with zero issues, this risk is minimal unless future code additions (from 4.1--4.3 if they add more tests) introduce warnings.
