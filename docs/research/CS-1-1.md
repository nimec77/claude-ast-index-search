## Summary

This ticket adds Flutter project detection to `ast-index` by recognizing `pubspec.yaml` as a project marker file. Four discrete tasks modify `src/indexer.rs` and `src/main.rs` to add a `ProjectType::Flutter` variant, detect it, resolve project roots, and recognize build markers.

### 2. `detect_project_type()` (`src/indexer.rs`, lines 145-243)

This function checks for marker files and returns the appropriate `ProjectType`. It uses a counting array to detect multi-platform projects:

```rust
let count = [
    has_gradle, has_swift, has_perl, has_frontend,
    has_python, has_go, has_rust, has_bazel,
].iter().filter(|&&x| x).count();
```

If `count > 1`, returns `ProjectType::Mixed`. Otherwise returns the single matched type, or `Unknown`.

**What must change:**
- Add `let has_flutter = root.join("pubspec.yaml").exists();`
- Add `has_flutter` to the count array
- Add `else if has_flutter { ProjectType::Flutter }` branch (after `has_bazel`, before `Unknown`)

### 3. `find_project_root()` (`src/main.rs`, lines 1000-1039)

This function walks up from `cwd` through ancestors, checking for:
1. Existing index DB
2. Gradle markers (`settings.gradle`, `settings.gradle.kts`)
3. iOS markers (`Package.swift`, `.xcodeproj`)
4. Bazel markers (`WORKSPACE`, `WORKSPACE.bazel`, `MODULE.bazel`)

Falls back to `cwd` if no markers found.

**IMPORTANT:** This function does NOT exist in `src/indexer.rs`. The phase-1.md description says "Update `find_project_root()` in `src/indexer.rs` and `src/main.rs`", but the function only exists in `src/main.rs`.

**What must change:**
- Add a `pubspec.yaml` check block, e.g.:
```rust
// Flutter markers
if ancestor.join("pubspec.yaml").exists() {
    return Ok(ancestor.to_path_buf());
}
```

**Notable gap:** The function also lacks checks for Python (`pyproject.toml`), Go (`go.mod`), Rust (`Cargo.toml`), Perl (`Makefile.PL`), and Frontend (`package.json`) markers. This ticket only requires adding `pubspec.yaml`; fixing the others is out of scope.

### 4. `has_build_marker()` (`src/indexer.rs`, lines 136-142)

This private function is used only in `find_sub_projects()` for monorepo sub-project detection. It currently checks:
- `ya.make`, `Makefile`, `BUILD`, `BUILD.bazel`, `CMakeLists.txt`

```rust
fn has_build_marker(path: &Path) -> bool {
    path.join("ya.make").exists()
        || path.join("Makefile").exists()
        || path.join("BUILD").exists()
        || path.join("BUILD.bazel").exists()
        || path.join("CMakeLists.txt").exists()
}
```

**Signature:** `fn has_build_marker(path: &Path) -> bool` -- no `ProjectType` parameter.

**Design decision:** The PRD identifies this as a design choice. Options:
1. **Add `pubspec.yaml` unconditionally** -- simplest approach. `pubspec.yaml` is a sufficiently specific marker that false positives are unlikely. This is the recommended approach.
2. **Change signature to accept `ProjectType`** -- would require updating the call site in `find_sub_projects()` which already has `pt` available. This is more correct but a broader refactor.

Since `has_build_marker` is only used to decide "does this subdirectory look like a project root for monorepo detection", adding `pubspec.yaml` unconditionally is safe and consistent with the existing pattern (e.g., `Makefile` is also a generic marker already in the list).

The codebase already has substantial Dart support that does NOT depend on this ticket:

- **File type:** `FileType::Dart` registered in `src/parsers/mod.rs` (line 368), extension `"dart"` mapped at line 394

This function determines which files are treated as module descriptors during indexing. Currently includes `build.gradle`, `build.gradle.kts`, `Package.swift`, `.pm` files, and `pom.xml`. Note: `pubspec.yaml` is NOT in this list. Adding it is part of Phase 2 (task 2.1), not this ticket.

## Dependencies and Layers

```
main.rs::find_project_root()
    -> determines project root (walks up ancestors)
    -> calls db::db_exists() and checks marker files

main.rs::main()
    -> calls find_project_root()
    -> passes root to command handlers

indexer.rs::detect_project_type()
    -> called during indexing in index_directory_scoped()
    -> result printed if progress=true
    -> NOT used by find_project_root() in main.rs

indexer.rs::has_build_marker()
    -> called only by find_sub_projects()
    -> used for monorepo sub-project detection

indexer.rs::find_sub_projects()
    -> calls detect_project_type() and has_build_marker()
```

---

## Patterns Used

- **Enum-based dispatch:** `ProjectType` enum with `as_str()` method and match arms in `detect_project_type()`
- **Marker file detection:** Boolean variables (`has_gradle`, `has_swift`, etc.) checked against filesystem, combined into count array for Mixed detection
- **Ancestor walking:** `find_project_root()` uses `cwd.ancestors()` iterator to walk up the directory tree
- **Test fixtures:** `tempfile::TempDir` with `fs::write()` to create marker files

## Limitations and Risks

1. **`has_build_marker()` design ambiguity (LOW RISK):** Adding `pubspec.yaml` unconditionally is safe because the marker is sufficiently specific. No signature change needed.

2. **Overlap with Frontend projects (EXPECTED):** A Flutter project that also has `package.json` will be detected as `Mixed`. This is correct behavior per the existing multi-platform detection logic.

3. **No `find_project_root()` in `indexer.rs` (DOCUMENTATION MISMATCH):** The phase description says to update this function in both files, but it only exists in `src/main.rs`. This is not a blocker -- only `src/main.rs` needs updating.

4. **Missing markers in `find_project_root()` (OUT OF SCOPE):** The function in `main.rs` lacks checks for Python, Go, Rust, Perl, and Frontend markers. This pre-existing gap is not part of this ticket.
