**Mandatory Search Rules** (identical to all platforms):
- ALWAYS use ast-index FIRST
- NEVER duplicate results
- DO NOT run grep "for completeness"
- Use grep/Search ONLY when ast-index returns empty, or searching regex/string literals/comments

**Why ast-index** (identical):
- 17-69x faster than grep

**Command Reference table** (3-column, Dart-adapted labels):

| Task | Command | Time |
|------|---------|------|
| Universal search | `ast-index search "query"` | ~10ms |
| Find class/mixin | `ast-index class "ClassName"` | ~1ms |
| Find symbol | `ast-index symbol "SymbolName"` | ~1ms |
| Find usages | `ast-index usages "SymbolName"` | ~8ms |
| Find implementations | `ast-index implementations "Parent"` | ~5ms |
| Call hierarchy | `ast-index call-tree "function" --depth 3` | ~1s |
| Class hierarchy | `ast-index hierarchy "ClassName"` | ~5ms |
| Find callers | `ast-index callers "functionName"` | ~1s |
| Module deps | `ast-index deps "module-name"` | ~10ms |
| File outline | `ast-index outline "widget.dart"` | ~1ms |

**Flutter-Specific Search Rules** (Task 3.2 -- NEW section, placed above the commands table):

Textual guidelines for Flutter development with ast-index:
- Use `ast-index implementations "StatelessWidget"` or `"StatefulWidget"` to find all widget implementations
- Use `ast-index implementations "Bloc"` or `"ChangeNotifier"` to find state management classes
- Use `ast-index class "Mixin"` to find mixins (indexed as Interface kind)
- Use `ast-index search "extension"` to find Dart extensions (indexed as Object kind)
- Use `ast-index hierarchy "Widget"` to explore the widget inheritance tree
- Use `ast-index conventions` to auto-detect BLoC, Provider, and other architecture patterns

## Deviations to Fix

### 1. PRD Scenario 5: `ast-index modules` does not exist

The PRD mentions `ast-index modules` in Scenario 5. The actual CLI command is `ast-index module "pattern"` (singular, requires a pattern argument). The plan uses `ast-index module "app"` (from the research's proposed table) in the Flutter Project Detection section, but does NOT include it in the main Flutter-Specific Commands table to keep the table focused on the most useful commands. The `ast-index map` command is included instead, which provides a project overview including module information.

### 2. Phase-3.md: `ast-index search --kind Class --lang dart` is invalid

The phase-3.md description uses `ast-index search --kind Class --lang dart` as an illustrative example. The `search` subcommand does not have `--kind` or `--lang` flags. The PRD (Constraint 4) already addresses this. The plan uses `ast-index class "ClassName"` for class searches and `ast-index symbol "SymbolName"` for other symbol kinds.

### 3. Existing `initialize-web.md` uses invalid flag (pre-existing, NOT fixed by this ticket)

The existing `initialize-web.md` contains `ast-index search "use" --kind function` which uses the non-existent `--kind` flag on `search`. This is a pre-existing issue. The Flutter command does NOT replicate this mistake. Fixing the web command is out of scope for CS-3-3.

## Risks

1. **Dependency on CS-3-1/CS-3-2 being bundled:** Since this ticket covers all 4 tasks, there is no actual dependency issue -- the file is created from scratch with all content. Risk is eliminated.
2. **State management framework coverage:** Flutter has many state management solutions. The plan focuses on BLoC, Provider/ChangeNotifier, and Cubit as the most prevalent patterns. Riverpod is covered in the optional Flutter Project Detection section but not in the commands table (since `ConsumerWidget` is Riverpod-specific and may not be in most projects).
3. **Mixin search via `class "Mixin"`:** Mixins are indexed as `Interface` kind, which means `ast-index class "Mixin"` will find them via substring match on the name. This works correctly but only finds mixins whose name contains "Mixin". This is a limitation documented in the research and consistent with how other platform commands work (e.g., Android's `class "Controller"` finds controllers by naming convention).
