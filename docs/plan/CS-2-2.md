### 2. Pubspec.yaml Branch in `index_modules_from_files()` (`src/indexer.rs`)

Add a new branch inside the `for path in files` loop in `index_modules_from_files()` (after the Maven/pom.xml block at line 1097 and before the closing `}` of the `if let Some(name)` block at line 1098).

**Implementation:**

1. Check `name_str == "pubspec.yaml"`
2. Get the parent directory
3. Compute the relative module path via `parent.strip_prefix(root).unwrap_or(parent)`
4. Read file content with `fs::read_to_string(path)`
5. Define a local `#[derive(serde::Deserialize)] struct PubSpec { name: Option<String> }`
6. Deserialize with `serde_yaml::from_str::<PubSpec>(&content)`
7. If `name` is `Some` and non-empty, insert into `modules` table with `INSERT OR IGNORE`
8. Increment `count`

**Code sketch:**

```rust
// Flutter modules (pubspec.yaml)
if name_str == "pubspec.yaml"
    && let Some(parent) = path.parent()
{
    let module_path = parent
        .strip_prefix(root)
        .unwrap_or(parent)
        .to_string_lossy()
        .to_string();

    if let Ok(content) = fs::read_to_string(path) {
        #[derive(serde::Deserialize)]
        struct PubSpec {
            name: Option<String>,
        }
        if let Ok(pubspec) = serde_yaml::from_str::<PubSpec>(&content) {
            if let Some(ref mod_name) = pubspec.name {
                if !mod_name.is_empty() {
                    conn.execute(
                        "INSERT OR IGNORE INTO modules (name, path) VALUES (?1, ?2)",
                        rusqlite::params![mod_name, module_path],
                    )?;
                    count += 1;
                }
            }
        }
    }
}
```

**Key design decisions:**
- `PubSpec` struct uses `name: Option<String>` so a missing `name:` field produces `None` rather than a deserialization error -- the file is gracefully skipped (Scenario 3).
- The struct is defined locally inside the branch, minimizing scope. This follows the precedent of `PERL_PACKAGE_RE` being defined inside the Perl branch.
- `serde_yaml::from_str()` failure (malformed YAML) is handled gracefully via `if let Ok(...)` -- no panic, no error propagation, just skip the file.
- The module `name` comes from the YAML `name:` field (e.g., `my_app`), NOT derived from the directory path. This matches the SPM pattern (names from file content) and differs from Gradle (names from path).
- The `module_path` is the relative path of the parent directory, consistent with all other branches.
- For root-level `pubspec.yaml`, `strip_prefix` produces `""`. This is acceptable because the name comes from YAML content, not the path. An empty path for the root module is consistent with how SPM handles root-level packages.

### 3. No Schema Changes Needed (`src/db.rs`)

The `modules` table already has the required columns (`id`, `name`, `path`, `kind`). The `kind` column is nullable and not used by any existing module parser. This ticket follows the same pattern and only inserts `name` and `path`.

No changes to `src/db.rs` are needed.

### 4. No Changes to `is_module_file()` (CS-2-1 Prerequisite)

This ticket assumes CS-2-1 has already added `|| name == "pubspec.yaml"` to `is_module_file()`. Without that change, `pubspec.yaml` files are never collected during the filesystem walk and never passed to `index_modules_from_files()`. The new branch would exist but never execute.

If CS-2-1 has NOT been completed, it must be completed first or concurrently with CS-2-2.

## API Contract

No public API changes. This ticket modifies internal indexing logic only.

- `index_modules_from_files()` gains a new branch for `pubspec.yaml` files. Its signature is unchanged: `fn(conn: &Connection, root: &Path, files: &[PathBuf]) -> Result<usize>`.
- The `modules` SQLite table receives new rows with `name` from `pubspec.yaml` `name:` field and `path` from the parent directory's relative path.
- `ast-index modules` automatically displays Flutter modules once they are in the `modules` table (no command-layer changes needed).

## Non-Functional Requirements

1. **Zero regressions:** All existing tests must continue to pass. Existing module parsing for Gradle, SPM, Perl, and Maven is unaffected.
2. **Lint compliance:** `cargo clippy -- -D warnings` must produce zero new warnings.
3. **Formatting:** Code must pass `cargo fmt` without changes.
4. **Performance:** Negligible impact. YAML parsing of a small `pubspec.yaml` file (typically a few KB) is lightweight. The `PubSpec` struct ignores all fields except `name`, so deserialization is fast.
5. **Pattern consistency:** The new branch must follow the established branch-by-filename pattern in `index_modules_from_files()`.
6. **Graceful failure:** Malformed YAML, missing `name:` field, or unreadable files are silently skipped (no error propagation, no crash).

## Risks

### Risk 1: `serde_yaml` Crate Maintenance Status (MEDIUM)

**Description:** The `serde_yaml` crate (v0.9.x) by dtolnay has been archived and is no longer maintained. The community fork `serde_yml` is the actively maintained replacement.

**Mitigation:** For the simple use case of extracting a `name:` field from YAML, `serde_yaml` v0.9 is stable and functional. The phase-2 description explicitly specifies `serde_yaml`. If the team decides to switch to `serde_yml`, the API is identical for this use case (only the import path changes). See ADR `docs/adr/CS-2-2.md`.

### Risk 2: CS-2-1 Must Be Completed First (BLOCKING)

**Description:** Without CS-2-1 adding `pubspec.yaml` to `is_module_file()`, the new parsing branch will never execute because `pubspec.yaml` files are never collected.

**Mitigation:** Verify CS-2-1 is complete before integration testing. Unit tests can be written independently using `TempDir` and direct calls to `index_modules_from_files()`.

### Risk 3: Duplicate Module Names in Monorepo (LOW)

**Description:** The `modules` table has a `UNIQUE` constraint on `name`. If two `pubspec.yaml` files define the same `name:` value, the second insertion is silently skipped by `INSERT OR IGNORE`.

**Mitigation:** Dart/Flutter package naming conventions require unique names within a project. In practice, duplicate names are rare and indicate a configuration error. The `INSERT OR IGNORE` behavior is consistent with all other module parsers.

### Risk 4: Root-level `pubspec.yaml` Produces Empty Path (LOW)

**Description:** If `pubspec.yaml` is at the project root, `parent.strip_prefix(root)` produces `""` as the module path.

**Mitigation:** The module name comes from YAML content (not the path), so it is always populated. An empty path for the root module is acceptable and consistent with how other parsers handle root-level module descriptors.
