**Ticket:** CS-5
**Status:** PLAN_APPROVED

## Scope

CS-5 covers Phase 5 of the project: a comprehensive codebase refactoring to reduce duplication, remove dead code, split large modules, and extract magic values. All changes are structural only -- no observable behavior may change. The phase comprises 9 sub-tasks (5.1--5.9), each independently committable, with 5.9 marked optional.

### 4. File Search Unification (Task 5.4)

**Files:** `src/commands/mod.rs`

Make `search_files` delegate to `search_files_limited` with `usize::MAX`:

```rust
pub fn search_files<F>(
    root: &Path,
    pattern: &str,
    extensions: &[&str],
    handler: F,
) -> Result<()>
where
    F: FnMut(Arc<Path>, usize, String) + Send + 'static,
{
    search_files_limited(root, pattern, extensions, usize::MAX, handler)
}
```

Remove the ~100 lines of duplicated WalkBuilder/channel body from `search_files`.

**Channel bound concern:** With `limit = usize::MAX`, the expression `limit.max(1000)` in `search_files_limited` evaluates to `usize::MAX`, creating an excessively large channel bound. Fix this in `search_files_limited` by capping the channel bound: `channel::bounded(limit.min(10_000).max(1_000))`. This preserves the original behavior for `search_files` callers (which previously used `bounded(10000)`) and adds a sensible cap for limited callers.

### 5. WalkBuilder Ignore Setup Helper (Task 5.5)

/// Configure arc/gitignore handling on a WalkBuilder.
pub fn configure_walk_ignores(builder: &mut WalkBuilder, arc_root: Option<&Path>) {
    if let Some(arc) = arc_root {
        builder.add_custom_ignore_filename(".gitignore");
        builder.add_custom_ignore_filename(".arcignore");
        let root_gitignore = arc.join(".gitignore");
        if root_gitignore.exists() {
            builder.add_ignore(root_gitignore);
        }
    }
}
```

Replace 5 duplicated blocks:
- `src/indexer.rs`: 3 blocks (in `index_directory_scoped`, `update_directory_incremental`, `index_modules`)
- `src/commands/mod.rs`: 1 block (in `search_files_limited`, after Task 5.4)

The `configure_walk_ignores` function will need to be importable by the command modules via `crate::indexer::configure_walk_ignores`.

/// Build a rayon thread pool, respecting AST_INDEX_THREADS env var.
fn build_thread_pool() -> Result<rayon::ThreadPool> {
    let num_threads = std::env::var("AST_INDEX_THREADS")
        .ok()
        .and_then(|v| v.parse::<usize>().ok())
        .unwrap_or_else(|| std::cmp::min(8, rayon::current_num_threads()));

        .num_threads(num_threads)
        .build()
        .map_err(|e| anyhow::anyhow!("Failed to build thread pool: {}", e))
}
```

## NFR (Non-Functional Requirements)

1. **Zero behavioral changes:** No observable output, query result, or error behavior may change for any command.
2. **Incremental verifiability:** Each sub-task (5.1--5.9) must independently pass `cargo fmt --check`, `cargo clippy -- -D warnings`, and `cargo test`.
3. **Full acceptance criteria:** After all tasks complete: `cargo fmt --check && cargo clippy -- -D warnings && cargo clippy --tests -- -D warnings && cargo test && cargo test --test memory_tests -- --test-threads=1` must pass with zero errors and zero warnings.
4. **Net code reduction:** Estimated ~400-500 lines of duplicated code removed across all tasks.
5. **Module size reduction:** `indexer.rs` reduced from ~2992 lines to ~500-600 lines (re-exports and shared types). `db.rs` reduced from ~1468 lines to ~700-800 lines (if Task 5.9 is performed).

## Risks

1. **Subtle behavioral drift from guard helper (Task 5.2):** The helper must exactly reproduce the existing guard behavior (print the same red warning, return `Ok(())`). Risk is low since all 24 blocks are confirmed identical, but each replacement site must be verified.

2. **Channel bound regression (Task 5.4):** When `search_files` delegates to `search_files_limited` with `usize::MAX`, the channel bound expression `limit.max(1000)` produces `usize::MAX`. This must be addressed by capping the channel bound at `limit.min(10_000).max(1_000)` to avoid allocating an enormous buffer.

3. **Re-export completeness (Tasks 5.8, 5.9):** Moving functions into sub-modules risks breaking callers if any `pub use` re-export is missing. Mitigation: run `cargo build` after every function move; use `pub use <submodule>::*;` as a safe starting point, then tighten exports if desired.

4. **Visibility adjustments (Task 5.8):** Several internal types (`ModuleLookup`, `ParsedFile`) and helpers (`parse_file`, `write_batch_to_db`, `is_module_file`) are currently private but will need `pub(crate)` or `pub(super)` visibility when accessed from child sub-modules. Each must be audited.

5. **Conventions conflict:** `docs/conventions.md` says "Use `mod.rs` for module entry points" but the PRD requires Rust 2024 file-based modules (no `mod.rs`). The PRD takes precedence as the authoritative requirement. The conventions file may need a note added if the team decides to adopt file-based modules going forward.

6. **Dead code extent unknown (Task 5.1):** Removing `#![allow(dead_code)]` from `db.rs` may surface an unknown number of dead-code warnings. Each must be assessed individually -- some functions may be genuinely dead and removable, others may be used only in tests or planned for future use.
