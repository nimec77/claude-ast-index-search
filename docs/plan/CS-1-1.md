## API Contract

No public API changes. This ticket modifies internal detection logic only.

- `ProjectType::Flutter` becomes a new public enum variant (used by downstream commands)
- `detect_project_type()` returns `ProjectType::Flutter` when `pubspec.yaml` is found alone
- `detect_project_type()` returns `ProjectType::Mixed` when `pubspec.yaml` coexists with other project markers
- `find_project_root()` returns the ancestor containing `pubspec.yaml`
- `has_build_marker()` returns `true` for directories containing `pubspec.yaml`

## Data Flows

```
User runs `ast-index index` from /projects/my_app/lib/src/
    |
    v
find_project_root() [src/main.rs]
    walks up: lib/src/ -> lib/ -> my_app/ (has pubspec.yaml) -> RETURN
    |
    v
index_directory_scoped() calls detect_project_type(root)
    checks root.join("pubspec.yaml").exists() -> true
    count array has 1 true -> returns ProjectType::Flutter
    |
    v
ProjectType::Flutter.as_str() -> "Flutter (Dart)" (printed if progress=true)
    |
    v
find_sub_projects() calls has_build_marker() on subdirectories
    pubspec.yaml in subdirectory -> recognized as sub-project boundary
```

## Risks

### Risk 1: `has_build_marker()` false positives (LOW)

**Description:** Adding `pubspec.yaml` unconditionally to `has_build_marker()` could theoretically cause non-Flutter subdirectories to be detected as sub-projects.

**Mitigation:** `pubspec.yaml` is a highly specific marker (only Dart/Flutter projects use it). The existing function already includes generic markers like `Makefile`. The risk of false positives is negligible. See ADR `docs/adr/CS-1-1.md`.

### Risk 2: Flutter+Frontend overlap triggers Mixed (EXPECTED)

**Description:** Flutter projects often contain `package.json` (e.g., for web tooling), which would trigger `ProjectType::Mixed` instead of `ProjectType::Flutter`.

**Mitigation:** This is correct behavior per the existing multi-platform detection logic. No special handling is needed in Phase 1. The PRD explicitly confirms this in Scenario 3.

### Risk 3: `find_project_root()` documentation mismatch (RESOLVED)

**Description:** Phase-1.md task 1.3 references `find_project_root()` in `src/indexer.rs`, but the function only exists in `src/main.rs`.

**Mitigation:** Implementation updates only `src/main.rs`. The research document confirms this deviation and it does not affect correctness.
