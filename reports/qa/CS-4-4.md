## Risk Zone

### RISK-1: Nightly toolchain churn (LOW)

**Detail:** The project uses `channel = "nightly"`, specifically `rustc 1.96.0-nightly (38c0de8dc 2026-02-28)`. Nightly updates can introduce new clippy lints between the verification date and any future merge/release. If the nightly changes before the PR is merged, CI could fail even though local verification passed.

**Mitigation:** The plan documents this risk. If CI fails on a new lint, fix the lint under the same constraints (no suppression, no behavioral change). Pinning the nightly date in `rust-toolchain.toml` is available as a last resort.

**Blocking for release:** No. The current verification is clean on the current nightly.

### RISK-2: No automated enforcement of "no new `#[allow(...)]` annotations" policy (LOW)

**Detail:** The zero-new-suppression constraint is enforced by convention and code review, not by an automated check. A future contributor could add a `#[allow(clippy::...)]` without triggering a CI failure.

**Mitigation:** This is a process risk, not a code risk. The three permitted annotations are documented. A CI step using `grep` to count `#[allow(clippy` occurrences could be added in a follow-up ticket.

**Blocking for release:** No.

### RISK-3: Test count discrepancy if 4.1-4.3 results differ from expectation (LOW)

**Detail:** The plan states "398+ tests" and the tasklist confirms 398 (379 unit + 19 memory). If tasks 4.1-4.3 were expected to add specific tests that are not yet present, the 398 count may not reflect the intended final state.

**Mitigation:** Cross-reference the 398 count against the acceptance criteria of CS-4-1, CS-4-2, and CS-4-3. If those tickets define specific test names, confirm they appear in the test output.

**Blocking for release:** No -- unless the cross-reference reveals that expected tests from 4.1-4.3 are absent. This is LOW probability given the tasklist is marked IMPLEMENT_STEP_OK.

### RISK-4: Cascading change risk (MITIGATED, RESIDUAL LOW)

**Detail:** The plan noted that a clippy fix in a core module (`indexer.rs`, `db.rs`) could affect downstream behavior. In practice, no fixes were applied (the baseline was already clean), so this risk did not materialize.

**Residual risk:** If a future clippy run on the same code produces warnings (e.g., due to nightly update), the cascade risk is still present.

**Blocking for release:** No.
