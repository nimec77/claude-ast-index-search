## Negative and Edge Cases

### EC-1: #[path] module isolation -- test-only items not leaking

The `#[path = "dart_tests.rs"] mod tests;` pattern is wrapped in `#[cfg(test)]`, which means the test file is compiled only in test mode. The `use super::*;` at the start of each `*_tests.rs` file gives tests full access to the parent module's private API, matching the behavior of an inline test module. This is the standard Rust pattern and is correctly applied in all four test files.
**Verdict:** No leakage risk.

### EC-2: Dart error recovery -- shared helper visibility

`find_first_identifier`, `find_first_type_identifier`, and `find_descendant_by_kind` are used by non-error-recovery code in `dart.rs` (9 call sites). These are exposed as `pub(super)` in `dart_error_recovery.rs` and called via `error_recovery::` prefix in `dart.rs`. The `pub(super)` visibility correctly restricts access to the parent module only.
**Verdict:** Correctly isolated.

### EC-3: walk_body_declarations visibility widening

The plan identified a risk that `walk_body_declarations` needed to be `pub(super)` so the `error_recovery` submodule can call it. Confirmed: `walk_body_declarations` is `pub(super) fn` at line 647 of `dart.rs`. This is a visibility-only change with no behavioral impact.
**Verdict:** Risk resolved correctly.

### EC-4: management.rs size after 6.2.2

Adding `cmd_install_claude_plugin()` (~52 lines) to `management.rs` was flagged as a low risk that would bring it to ~1009 lines. The plan documented this as acceptable for this phase. This is not a quality gate failure -- no file size limit is enforced by the CI toolchain. It is noted as a minor NFR concern for a future phase.
**Verdict:** Known and accepted deviation.

### EC-5: Binary crate module imports in cli.rs

`cli.rs` is a module of the binary crate (not the library). The plan required using `ast_index::db` rather than `crate::db` for library imports. This was identified as a low risk and was to be handled by the implementer.
**Verdict:** Not independently verified (no failures in `cargo build` or `cargo test` confirm it is handled correctly).

### EC-6: dart.rs does not import find_capture from super

`dart.rs` does not include `find_capture` in its `use super::` import, consistent with the observation that `dart.rs` itself has no direct calls to `find_capture`. Dart's query processing is structured differently -- it does not use the generic `find_capture` helper. This is correct behavior; the deduplication task only targeted parsers that actually used the function.
**Verdict:** Correct omission.

### EC-7: find_capture signature identity across 14 parsers

The plan noted this risk was resolved during research: "All 14 copies are byte-identical." Since the shared implementation in `mod.rs` matches the common signature, and all 14 parsers now import from `super`, any divergence would have produced a compile error. No compile errors exist.
**Verdict:** Confirmed clean by successful `cargo test`.

## Risk Zone

### Risk 1: No independent sub-task commits (Medium)

The constraint specified in the PRD and tasklist is: "Each sub-task should be committed independently after passing all checks." The current working tree contains all ten sub-tasks as unstaged modifications and untracked files, with no commits on the `feature/cs6-phase6` branch beyond the documentation commits from Phase 5 planning. This is the same pattern observed in CS-5.

**Impact:** If the branch is reverted or bisected, there is no way to isolate which sub-task introduced a regression. However, since all checks pass in the final state, the risk is process-only with no code-correctness impact.
**Severity:** Low (process). No code defect.

### Risk 2: management.rs exceeds 1000 lines (Low)

`management.rs` is projected at ~1009 lines after adding `cmd_install_claude_plugin` (52 lines to the previous ~957 lines). This was documented as an accepted deviation in the plan. The file is not subject to an automated size gate and the PRD explicitly noted this as a future-phase concern.
**Impact:** Minor NFR deviation. No functional impact.
**Severity:** Low.

### Risk 3: IDE/tooling support for #[path] attribute (Low)

The `#[path = "..."]` attribute is a known Rust pattern supported by rust-analyzer and RustRover. However, some IDE versions may show incomplete navigation between the parser file and its `*_tests.rs` file. This is an ergonomics concern, not a correctness concern.
**Impact:** Potential developer experience degradation in some IDE configurations.
**Severity:** Low.

### Risk 4: install-claude-plugin smoke test not run (Low)

The `cmd_install_claude_plugin()` function was relocated from `main.rs` to `management.rs`. While the function body is identical (copy-move), the runtime behavior of installing the Claude plugin was not manually smoke-tested in this QA session. The `cargo test` suite does not include an integration test for this command. The function uses `std::process::Command` internally and does not interact with the indexed DB.
**Impact:** Potential undetected regression in the plugin installation command.
**Severity:** Low. The code is a straightforward copy; the function was not modified.
